## A2. Runtime binding, conceptual tables and destruction
An ordinary nonvirtual call is selected from the static type. With Bill* b pointing at an OutPatientBill, b->total() selects the final overrider at run time because total is virtual. In the supplied example, b->show() itself binds to Bill::show; the call to total() within show still dispatches to OPBill::total. The predicted output was recorded before execution in A2/prediction.txt and matched 500 ~OPBill ~Bill followed by a newline, including the trailing space.

Conceptual dispatch: Bill object → vptr → OutPatientBill virtual table → OutPatientBill::total. Conceptual Bill table contains destructor entries and pure total/type slots; OutPatientBill and InPatientBill tables contain their overridden total/type functions and derived destructor entries, plus inherited packageCode. C++ does not mandate vtables, their layout or a single vptr, so these are explanatory diagrams, not an ABI dump. Actual sizeof measurements are reported in B3.

A base destructor must be virtual when an object will be deleted through a base pointer. The original tiny example without virtual destruction (and with the now-invalid derived destructor override specifier removed) printed 500 ~Bill here and ASan emitted no error. This is still undefined behavior, not evidence of safety. Equal allocation/deallocation sizes can evade this sanitizer check. In the fuller B1 example, ASan detected new-delete-type-mismatch. No portable output prediction exists for undefined behavior.

Alternative: retain a polymorphic base solely for RTTI, use dynamic_cast to test up to k known derived types, then invoke a nonvirtual function. One virtual dispatch is conventionally O(1); a chain makes up to k RTTI operations per bill. Individual dynamic_cast cost is ABI/hierarchy-dependent, not guaranteed constant by the language. This alternative still needs a polymorphic base for checked downcasts, so it does not inherently eliminate the vptr. It also centralizes type knowledge and is weaker for extension.
