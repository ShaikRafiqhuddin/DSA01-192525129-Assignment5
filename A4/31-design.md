## A4. Exception strategy
The hierarchy is std::exception → std::runtime_error → BillingError; InvalidCharge and MissingPatient derive from BillingError; ClaimError derives from BillingError and UnknownPackage from ClaimError. std::invalid_argument (stod) and std::bad_alloc stay standard exceptions. Reject nonfinite/negative charges, negative days, empty patient ID, invalid copay, above-cover claims and unknown packages. An empty-ID check models missing patient data; a real service must query and validate the authoritative patient record.

Constructors, total(), amountCovered(), print(), parsing and persistence may throw. Bill/Payer destructors are noexcept and own only safe RAII members. patient() is a non-allocating reference getter and is noexcept. name/type are not noexcept because returning std::string can allocate. Destructors must not throw while another exception is unwinding; a second escaping exception would call std::terminate. Logging at an error boundary must itself be protected or nonthrowing.

Alternative: Status approve(input, output, message) returns an enum and a caller branches on it. For fixed validation, both normal status and normal exception-enabled paths have O(1) work; throwing adds implementation-dependent allocation, handler search and O(d) stack unwinding for depth d. A message of length m needs O(m) storage/copy work. Return codes add branches at every propagation boundary and may be ignored. Exceptions keep the successful return value uncluttered but must not be used for frequent expected rejection. Results are measured in B3.
