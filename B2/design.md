## B2. Engineered failures and exception identity
Seven independent cases test negative charge, claim above cover, unknown government package, std::stod text parsing, impossible allocation, missing patient ID and an unknown integer exception. Each case constructs a Guard and verifies alive returns to zero. The loop continues after every case. The impossible request uses SIZE_MAX bytes through operator new in the ordinary error test, and std::bad_alloc is actually caught; it does not attempt to consume all available memory. This allocation test is not passed to ASan, whose allocator may terminate for oversized requests by default. B4 separately supplies the requested clean sanitizer run with exceptions.

The B2 pre-run prediction matches exactly: ok done caught negative [log too large] caught too large . Only out_of_range is caught in process, so only that failure is logged and rethrown. The complete-code exercise yields approved 40000; audit: exceeds cover; claim rejected: exceeds cover; error: negative amount, each on its own line. The audit output uses throw; and preserves the same exception object.

throw e; copies an object using the static type of e. In the supplied ClaimError-only example, it still has type ClaimError, so no observable type difference is required. The extra rethrow.cpp test throws SpecificClaim, catches const ClaimError&, then compares both forms: throw; preserves SpecificClaim, while throw e; slices to ClaimError. This avoids falsely saying throw e always changes the type in the original example.

Alternative: std::optional<double> returns nullopt on rejection. It loses the reason unless paired with a status; expected/error types suit multiple rejection causes. It is O(1) per fixed validation and usually carries a value plus an engaged flag/padding. sizeof(optional<double>) is 16 bytes here versus 8 for double; these are implementation-specific. B3 measures one million cases for 0%, 1%, 50% invalid, using the same dataset for all three approaches.
