## B3. Experimental method and interpretation
Compile the benchmark with g++ -std=c++17 -Wall -Wextra -O2. The performance runs do not use ASan; instrumented memory tests are separate. x86_64 Linux, g++ 11.4.0, two visible logical CPUs. Each timed traversal has one warm-up and three measured passes; the median is reported in milliseconds. Initialization, allocation and destruction are excluded from timing. Virtual records own separately allocated objects, while switch/variant records are contiguous, so the result measures dispatch together with layout/cache effects, not an isolated virtual-call instruction cost. Representations are constructed sequentially to limit peak memory. The first four records force coverage of all four bill types; the remainder use fixed-seed xorshift data; seed 20261123; error datasets contain exactly 0, 10000 or 500000 invalid records, shuffled deterministically. The volatile checksum prevents dead-code removal. All representation checksums agree; small 10-record result is 9276. At this duration the 10/1000 cases approach clock resolution and should not support strong conclusions.

All traversals are O(n); the three measured curves differ by constants and memory locality. For 10 million records, the virtual loop was about 1.39× the switch loop in this run. sizeof virtual payload object 32, unique_ptr 8, tagged record 32, variant record 32 bytes. A 10-million virtual list therefore uses about 400 MB for pointer slots plus object payloads before allocator overhead; switch/variant payload is about 320 MB. No memory benchmark is claimed; these are size-based estimates. Every representation also has container overhead. The variant is largest-alternative storage plus discriminator and alignment; it does not always equal this 32-byte observation.

At 0% rejection, all successful paths are fast; exception support is not free in this exact program but the measured difference is a few milliseconds per million. At 50% rejection, throwing dominates. Normal validation failures should use explicit results, while unexpected domain/service failures can use typed exceptions at well-defined boundaries. Do not multiply a single run into a production capacity guarantee. Shared environment load, allocator, optimization, type ordering and hardware all affect these timings.
